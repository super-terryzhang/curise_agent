# 商品单位换算系统进度

日期：2026-09-24

## 当前结论

商品单位换算第一版已在隔离分支 `design/product-unit-conversion-20260924` 完成实现和本地验证。代码尚未推送、合并或部署；生产仍是数据库 `0030_direct_bulk_images`、后端 `cruise-v3-backend-order-issues-20260924` 和 2026-09-24 已核验前端，生产业务数据与规则均未被本次工作改写。

本次交付把单位问题拆为三层：确定的国际物理单位由程序精确计算；确认过的来源单位或商品包装关系由可审核规则复用；其余情况保留原始 PO 数据并要求人工确认。系统不会从 `KG2.2`、`CA2.27` 的数字后缀自行推导数量，也不会猜测能否拆包或自动取整。

## 已完成

- 新增 expand-only 迁移 `0031_unit_conversion_rules`，保存来源单位规则、商品包装规则、有效期间、换算基数、订购步长、拆包三态、证据、审核人、版本和时间戳；迁移不回填业务事实。
- 新增 Decimal 换算服务：同单位、标准重量/体积换算、商品包装规则优先、来源单位规则回退、冲突/过期/包装变化/步长不满足均有明确结果。
- 匹配流程在功能开关开启时只应用已验证且作用域完全一致的规则；单行异常隔离，不停止同一订单其他行或 Oracle 扫描。
- 订单人工处理支持“仅当前行”“相同商品及包装”“精确来源单位组合”三个范围；默认仅当前行，后两个范围仅管理员可用，保存与订单重匹配在同一事务完成。
- 询价准备只信任完整且已验证的换算快照；旧的文件级人工批准仍作为兼容兜底，不改写历史询价。
- 前后端换算数量均避免二进制浮点：整数保存为 JSON 整数，小数保存为精确十进制字符串；前端保留用户输入文本并交给后端 Decimal 校验。
- 新增只读影子审计脚本；PostgreSQL 上显式执行只读事务，未解决业务行正常出现在报告中，只有基础设施或查询失败才以非零状态退出。

1. 推送分支、创建 PR，要求后端与前端 CI 绿色后正常合并，不 force-push。

4. 在功能开关关闭时核验健康、OpenAPI、401、权限、CORS 和只读审计；再开启开关、切换后端流量、发布前端，并让 Oracle Job 使用同一镜像 digest。
5. 通过受控 API 创建五条草稿，分别运行不含草稿和含草稿的只读影子审计；不在发布脚本中验证规则。
