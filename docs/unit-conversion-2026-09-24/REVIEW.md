## 已发现并修复

### Important：后端换算快照经过二进制 float

订单匹配把 Decimal 小数转成 `float`，询价准备又重复转一次，循环小数或长小数会在写入 JSON 时失真。先新增两个失败测试复现，再引入共享的“整数或精确十进制字符串”序列化边界，并把新人工输入字段改为 Pydantic Decimal；积分数量仍以整数保持兼容。

### Important：前端在 Decimal 之前丢失精度

换算表单使用 `Number(value)` 的结果作为请求值，意味着长小数尚未到后端就已被舍入。回归测试先证明 `0.10000000000000000001` 变成 `0.1`，随后改为只校验正数、原样提交十进制文本，由后端 Decimal 作最终校验与运算。

### Important：启动迁移门禁测试仍接受旧 head

完整回归发现安全测试仍把 `0030_direct_bulk_images` 视为当前迁移，无法反映应用启动时对 0031 的真实要求。测试现明确断言 0030 被拒绝、0031 才通过；修复后完整后端回归为 1811 项通过。

## 重点审查结果

- **重复逻辑：** 公式和规则选择只存在于 masterdata 换算服务；订单协调器只保存快照，询价层只验证快照一致性。旧文件级批准路径暂时保留是明确的向后兼容兜底，不作为新规则计算器。
- **浮点强制转换：** 规则、公式、步长判断、人工关系比较、订单/询价业务快照和前端请求均不再通过二进制 float。Excel 单元格最终写入属于展示边界，Excel 自身使用数值单元格，不反向决定规则或业务数量。
- **领域边界：** orders 和 inquiry 只经 `domains.masterdata.service` 或 masterdata 包公开接口访问跨域能力；`scripts/check_arch.py` 报告 0 违规。
- **拆包判断：** `break_pack` 为可空三态，未知不会被解释为允许或禁止；只有已知 `target_step` 不满足时才产生 `NON_INTEGER_PACKAGE_QUANTITY`，系统不取整。
- **旧人工证据：** 已验证的当前行人工决定优先，保证重跑幂等；编辑 PO 行或重新关联商品会清除旧快照并重匹配。可复用商品规则用当前 `unit/unit_size/pack_size` 指纹防止包装变化后静默复用。
- **作用域：** 来源系统、来源单位、目标单位均规范化后精确匹配；商品规则额外要求 product id 和包装指纹完全一致。不存在前缀、模糊单位或候选商品自动选择。
- **异常隔离：** evaluator 异常被转换为当前行 `UNIT_CONVERSION_EVALUATION_FAILED`，下一行继续；规则缺失、冲突、过期、包装变化和步长问题保留各自错误码与动态处理建议。
- **数据库一致性：** partial unique index 阻止同一精确作用域存在两条已验证规则；创建规则、审核规则、保存当前订单和重新匹配处于同一事务。迁移为空表扩展，不回填或猜测现有数据。
- **权限：** 普通处理人员只能保存当前行；商品或全局来源单位规则需要管理员，HTTP 和 service 双层测试证明无权限时没有部分写入。
- **审计安全：** PostgreSQL 影子审计在事务起点设置 READ ONLY，始终 rollback；业务未解决行不会伪装成脚本失败，连接或查询异常才非零退出。
