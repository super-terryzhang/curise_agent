# 产品整体有效期移除与采购价期间迁移设计

日期：2026-10-01

## 目标

产品是否可以参与匹配只由启用状态、国家和港口决定，不再由 `products.effective_from/effective_to` 控制。旧的产品整体有效日期尽可能原样迁入采购价有效日期；装船日没有命中采购价期间时，商品仍保持匹配成功，只增加“采购价期间未配置/未命中，需要复核”的非阻塞提示。

## 已确认的业务规则

- 产品整体有效期不是独立业务概念，最终从数据库、API、前端、Excel 模板和 Agent 工具中删除。
- 采购价和卖价期间相互独立，均以 `v3_product_price_periods` 为规范历史记录。
- 采购价按装船日选择；缺少装船日、未配置采购价期间或装船日没有命中期间，都不能把已匹配商品改成“未匹配”。
- 已有采购价日期和规范价格期间优先；旧产品日期只补空白，不覆盖已维护的采购价数据。
- 不能推测残缺或错误日期。无法安全迁移的原始值必须留下审计记录，之后由人工处理。
- Excel 旧表头不能被静默忽略，必须明确提示改用采购价开始/结束日期。

## 数据设计

### 迁移阶段 A：安全回填

新增迁移 `0033_product_validity_backfill`：

1. 建立 `v3_product_validity_migration_audit` 审计表，为所有被检查或修改的旧数据保存产品 ID、旧日期、迁移前采购价日期、处理结果、问题代码和本次创建的期间 ID；这样安全迁移也能精确降级，异常值不会丢失。
2. 对不会形成倒置区间的产品，仅用旧 `effective_from/effective_to` 填补为空的 `purchase_price_effective_from/to`。
3. 当采购价、开始日、结束日齐全且区间有效时，若没有相同或重叠的启用采购价期间，创建规范采购价期间；已有期间绝不覆盖。
4. 单边日期允许原样迁入兼容字段，但不虚构另一端、也不创建规范期间。
5. 倒置区间、重叠区间和同区间金额冲突在审计表中标记为 `review_required`，不自动修正。

### 迁移阶段 B：物理删除

新应用已经停止读写旧字段并完成生产冒烟后，运行 `0034_drop_product_validity` 删除 `products.effective_from/effective_to`。其 downgrade 会重新建立字段并使用审计表中的原始值；0033 的 downgrade 会删除本次创建的期间并恢复迁移前采购价日期，以保留精确回退能力。

## 匹配设计

候选商品只按 `status=true`、国家和港口筛选。价格解析单独使用装船日；无装船日或未命中采购价期间时，匹配结果保留产品与供应商，只在问题列表中加入可复核提示。

询价单仍可生成。该提示属于“匹配成功但需复核”，不能增加未匹配商品数量，也不能阻断同一 PO 的其他商品。

## 产品与上传设计

- 产品新增、编辑、详情和列表不再显示或接收产品整体有效日期；“有效/无效”仅表示产品启用状态。
- 批量上传只接受采购价开始/结束日期和卖价开始/结束日期。重复产品行可用于添加多个不重叠价格期间。
- 标准模板继续面向新增产品，不要求用户填写技术 ID；从产品页导出的更新文件额外携带只读的 `product_id`、`expected_revision`、`purchase_price_period_id` 和 `selling_price_period_id`。导出文件为每个产品提供一行产品资料，后续价格期间各占一行且不重复产品可变字段，避免修改一个字段后被其他期间行的旧值覆盖。
- 有 `product_id` 的行只能更新该产品，且名称、国家、港口必须仍与数据库身份一致；版本已经变化时整行拒绝，不能重新匹配到另一条产品。
- 价格期间 ID 为空表示新增一个完整期间；价格期间 ID 存在表示更新唯一的既有期间，允许修改金额、币种和起止日期。ID 必须属于该产品和对应价格类型。
- 没有期间 ID 时若区间已经存在，系统不得把“新增”猜成“更新”，而应提示用户重新导出并保留 ID。
- 同一产品、同一价格类型、相同区间但金额不同，必须在预览阶段报错；同批或数据库已有区间重叠也必须在提交前报错，不能产生部分成功。
- 批量回滚必须同步撤销该批次创建的规范价格期间，恢复产品兼容字段与价格历史。
- Agent 上传工具与静态 Excel 模板使用同一字段合同。

### 四种批量上传行为

1. **新增产品：** 无 `product_id` 且数据库不存在同一身份，创建产品；完整价格三元组同时创建价格期间。
2. **更新已有产品：** 有 `product_id + expected_revision`，只更新允许修改且非空的产品字段。
3. **新增已有产品的价格期间：** 产品已识别且对应 `*_price_period_id` 为空，完整填写价格和起止日期后创建不重叠期间。
4. **更新已有价格期间：** 对应 `*_price_period_id` 存在，以该 ID 的当前记录作为旧值，Excel 非空值作为新值，在预览显示旧值到新值并支持整批回滚。

## 发布与回退

1. 备份 Cloud SQL，运行 0033。
2. 部署停止使用旧字段的后端、Oracle Job 和前端，先以 Cloud Run 0% 流量候选验证。
3. 验证产品 CRUD、批量上传、订单匹配、询价生成和 Oracle 扫描后切流。
4. 再次备份，运行 0034，确认旧列已删除。
5. 若应用需要回退，先 downgrade 0034 恢复列，再回切旧镜像；0033 的规范价格期间和审计记录可由 downgrade 精确处理。

## 验收标准

- 数据库不再包含 `products.effective_from/effective_to`，且安全数据已迁入采购价兼容字段和规范期间。
- 数据库、后端、前端、Excel 模板和 Agent 工具不再提供产品整体有效期。
- 采购价期间缺失或未命中时，商品仍是匹配成功，只显示中文复核提示。
- 产品停用仍会阻止匹配；国家与港口筛选不变。
- 批量上传可为同一产品新增多个不重叠期间，重叠/冲突在预览阶段被完整拦截，回滚无残留。
- 相关后端测试、前端测试与构建、本地一次完整回归、GitHub CI、迁移往返、生产冒烟和 Oracle Job 均通过。
