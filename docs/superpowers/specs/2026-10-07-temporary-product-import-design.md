# 临时产品资料与价格区间导入设计

日期：2026-10-07  
状态：待用户确认；确认后再拆实施计划、更新新数据库并实现。  
目标环境：独立的新数据库 `cruise_v3_clean`，不得连接或写入当前生产数据库。

## 1. 目标

为新数据库提供一个临时、可撤除的准备页面，让管理员先配置数据字段，再通过一个 Excel 同时导入或更新产品资料与采购价／卖价区间。导入必须先检查、再预览、最后一次确认写入；产品资料、扩展字段和价格区间要么全部成功，要么全部不写入。

成功标准：

1. 产品以标准化后的“产品代码 + 港口”唯一识别，国家继续保存但不参与唯一判断。
2. 一个产品在 `产品资料` Sheet 中最多一行；一个产品可以在 `价格记录` Sheet 中拥有任意多个互不重叠的采购价或卖价区间。
3. 模板根据用户当前启用的产品字段配置实时生成，模板携带结构版本，旧模板在结构变化后不能直接写入。
4. 页面准确区分新增、更新、无变化、警告和阻止，并指出 Sheet、Excel 行、字段与原因。
5. 允许只上传产品资料而暂不配置价格，但明确提示“采购价未配置／卖价未配置”。
6. 临时页面和专用后端只连接新库；现有生产前端、Cloud Run 服务、Oracle Job 和生产数据库保持不变。

## 2. 代码与数据库现状（已核对）

1. 新库当前为 `0036_unified_data_tables`，业务表为空；产品、供应商、订单已登记为系统数据表。
2. `products` 仍保留历史兼容价格字段；正式多期间价格存放在 `v3_product_price_periods`，其精确边界已有唯一约束，业务服务也会检查同类价格区间重叠。
3. 当前产品上传器只读取工作簿第一个 Sheet，并把一行同时当作产品与价格数据，不能表达本设计的两个逻辑表。
4. 当前匹配仍按 `(country, code, port)` 或 `(country, name, port)`；代码注释提到的 `uix_country_product_name_port` 并不存在于当前 ORM／迁移定义，新建空库因此没有产品身份的数据库级唯一保护。
5. 当前 `v3_upload_batches + v3_staging_products` 是单 Sheet、单行模型；它无法可靠记录第二个 Sheet 的来源行、动态字段结构版本、跨 Sheet 引用及整批原子提交。
6. `v3_data_fields` 已支持单选字段和结构版本；系统产品表可以添加扩展字段并通过 `v3_data_records.source_record_id` 保存每个产品的扩展值。因此“业务分类”无需增加 `products` 物理列。
7. 现有系统数据表页面只支持核心记录关键词搜索和分页；它可继续用于字段配置，但不能直接代替本轮的双 Sheet 导入检查器。

## 3. 关键设计决定

### 3.1 应用隔离

采用“同一代码、独立临时环境”：临时前端连接一个临时 Cloud Run 后端，该后端只连接 `cruise_v3_clean`。不采用生产后端内部切换数据库，也不在浏览器传数据库名称，避免误写生产库及跨库权限漏洞。

临时页面建议路由为 `/dashboard/workbench/database-setup`，仅管理员可见，并由 `TEMP_DATABASE_SETUP_ENABLED` 控制。评估结束后关闭开关并删除入口；核心导入服务与测试可保留，临时导航和说明页面可撤除。

### 3.2 产品身份

规范化规则：产品代码去除首尾空格并进行不区分大小写比较；港口使用数据库 `port_id`。数据库建立“启用产品的标准化代码 + 港口”唯一约束，产品代码和港口在新库产品导入中为必填；国家仍是产品属性，不参与唯一判断。

同一文件出现相同产品键：

- 产品资料完全相同：保留一条并显示“重复、无变化”。
- 任一字段冲突：阻止整批，指出两条来源行。
- 价格记录允许同一产品多行，但同一价格类型的区间不能部分重叠。

### 3.3 产品字段

锁定核心字段：

- 产品代码
- 港口
- 产品名称
- 供应商
- 单位
- 商品分类（现有 `category`）
- 品牌
- 状态
- 国家（继续保存，但不参与身份）

可配置扩展字段从产品系统表的启用 `v3_data_fields` 读取。第一项预置扩展字段为“业务分类”，类型为单选，选项为“中标产品、未中标产品、临时产品、未分类”；默认“未分类”，管理员之后可在数据表管理中改名、停用选项或增加选项。

模板、暂存与导入只依据字段 ID 判断扩展字段；Excel 显示中文字段名，避免用户接触 UUID。字段重名在配置阶段禁止，保证 Excel 表头可以唯一反向解析。

### 3.4 一个工作簿、两个 Sheet

`产品资料`：每个唯一产品一行。包含当前启用的核心字段与扩展字段；技术列（记录 ID、产品版本、结构版本）由系统隐藏并保护，新增产品的记录 ID 为空。

`价格记录`：每个价格区间一行，字段固定为：

- 产品代码
- 港口
- 价格类型（采购价／卖价）
- 价格
- 币种
- 开始日期
- 结束日期
- 隐藏的价格区间 ID 与版本信息（已有记录导出时填写）

两张 Sheet 分别解析和校验，但属于同一个上传批次、同一个确认动作和同一个数据库事务。空 Sheet 表示本次不处理该类数据，不表示删除数据库内容。

### 3.5 模板生成

用户流程固定为：选择“产品” → 下载最新模板 → 编辑或新增 → 上传 → 程序检查 → 核对变更 → 确认导入。

模板由后端实时生成并包含：

- 当前产品表 `schema_version` 和模板契约版本；
- 当前启用字段及其类型、必填状态和选择项；
- 港口、供应商、分类、业务分类、状态、价格类型和币种的下拉校验；
- 产品代码按文本格式保存，价格为数字，日期为 `YYYY-MM-DD`；
- 锁定 Sheet 名和表头，并提供简短中文说明；
- 可按筛选范围导出当前数据；新库无数据时生成空白可填写模板。

模板结构版本过期时允许上传并读取，但在检查阶段阻止提交，提示用户下载最新模板；系统不得猜测已删除或改名字段。

## 4. 重复上传与更新规则

### 4.1 产品资料

- 数据库没有“产品代码 + 港口”：新增产品。
- 已存在且上传值相同：跳过。
- 已存在且普通字段不同：预览为更新。
- 用户把单元格留空：表示“不修改”；若要清空字段，模板提供明确的清空标记，不把空白猜成删除。
- 从 Excel 删除一行：不删除或停用数据库产品；状态变更必须显式填写。
- 现有产品导出后再上传：使用隐藏 ID 与版本做乐观锁；版本过期则阻止该批次提交。

### 4.2 价格区间

- 数据库没有相同产品、价格类型和日期边界：新增区间。
- 日期边界完全相同且价格、币种相同：跳过。
- 日期边界完全相同但价格或币种不同：按用户决定，直接更新该区间，并在预览中高亮旧值和新值。
- 与数据库或本文件其他行发生部分重叠：阻止提交，显示冲突区间。
- 有价格区间 ID：必须属于同一产品和价格类型；版本不一致时阻止提交。
- 开始日期晚于结束日期、价格不是合法非负数字、币种或价格类型无效：阻止提交。

### 4.3 关联与缺失

- 价格行引用的产品可以是数据库已有产品，也可以是本批次 `产品资料` 中即将新增的产品。
- 价格行找不到唯一产品：阻止提交，不自动创建半成品产品。
- 只有产品资料、没有采购价或卖价：允许提交；结果页与产品详情显示对应的未配置提示。
- 只有价格记录：仅当数据库已存在该产品时允许；否则阻止。

## 5. 检查与提交模型

### 5.1 新的暂存结构

保留旧上传表供现有生产流程使用，不直接改造其语义。新增隔离的导入结构：

- `v3_import_batches`：文件、目标表、模板版本、产品结构版本、状态、统计、创建人、时间和提交结果。
- `v3_import_rows`：Sheet、Excel 行号、行类型、原始值、规范化值、产品身份键、动作、问题列表及目标记录 ID。
- `v3_import_changes`：提交时记录产品核心字段、扩展字段和价格区间的前后值，用于审计与整批回滚。

批次状态：`uploaded → validating → ready → committed`，另有 `failed / cancelled / rolled_back`。批次内容一旦进入 `ready` 不可修改；重新上传创建新批次。

### 5.2 校验顺序

1. 文件、Sheet、模板契约和结构版本。
2. 表头与字段类型。
3. 单行值、下拉选项及必填字段。
4. Excel 内产品重复和价格区间冲突。
5. 主数据引用：港口、供应商、商品分类等必须唯一存在。
6. 与数据库产品、扩展字段和价格区间比对。
7. 生成新增、更新、跳过、警告、阻止统计和差异预览。

任何“阻止”项默认阻止整批提交。用户可回到 Excel 修正；第一版不提供在页面中忽略错误行，以避免产品与价格变成不完整的局部写入。

### 5.3 原子提交和并发

提交前重新锁定涉及的产品并复查产品版本、字段结构版本及价格区间。产品核心数据、扩展值、价格区间、历史记录与批次状态在一个数据库事务中写入；任意一步失败全部回滚。

重复点击使用批次 ID 幂等处理：已提交批次只返回原结果，不再次写入。保存结果不确定时，页面提供“核对提交结果”，不要求用户盲目重试。

## 6. 页面设计

临时页面沿用当前系统的紧凑业务风格，不新增看板或装饰组件：

1. **准备状态**：显示新库连接标识、产品表字段版本、字段数量和业务数据数量；提供“配置字段”和“开始导入”。
2. **下载模板**：选择空白模板或按当前筛选导出现有数据；明确模板生成时间与结构版本。
3. **上传与检查**：自动执行检查；顶部展示新增／更新／无变化／警告／阻止，下面按 Sheet 和行显示问题。
4. **核对变更**：产品资料与价格记录两个标签；旧值在左、新值在右，变化字段高亮。
5. **确认与结果**：只有无阻止项时可提交；结果列出实际新增、更新、跳过数量及批次编号。

产品数据展示继续采用数据库式列表：每个产品一行，列包含产品代码、港口、名称、供应商、单位、商品分类、品牌、业务分类和状态。点击产品进入详情页，上部为产品资料，下部分别显示采购价区间与卖价区间；每个区间一行，按开始日期升序排列，并显示已结束／当前／未来状态。

## 7. 数据库更新顺序

本轮在新库执行，生产库不执行：

1. 增加下一版迁移，建立标准化产品身份键及“产品代码 + 港口”的数据库唯一保护；由于新库产品为空，不需要清洗数据。
2. 增加新的导入批次、行和变更历史表及其约束／索引。
3. 更新 fresh bootstrap 基线，使未来空库直接包含同一结构。
4. 通过受控种子脚本在产品系统表创建“业务分类”扩展字段及四个稳定选项；脚本按固定 UUID 幂等执行。
5. 对新库运行迁移和只读审计，确认生产库未变化、业务表仍为空、只增加预期配置数据。
6. 完成后端和前端，再部署独立临时环境连接新库；不修改正式域名和正式服务变量。

## 8. 代码范围

预计新增／修改范围（实施计划会进一步拆到具体任务）：

### 后端

- 新迁移：产品身份约束与新导入暂存／历史表。
- `domains/imports/`：模板契约、动态字段目录、双 Sheet 解析、校验、差异、提交、回滚。
- `apps/http/`：临时导入 API、模板下载和批次查询。
- `domains/dynamic_data/`：只复用字段定义与值校验，不改变现有系统表核心字段保护。
- `domains/masterdata/`：抽取不自行提交事务的产品／价格写入原语，供原有 API 和新导入协调器共同使用。
- `scripts/`：幂等字段种子、新库审计和临时环境检查。

### 前端

- `app/dashboard/workbench/database-setup/`：临时五阶段页面。
- `lib/`：模板、批次、检查、预览、提交和结果 API 类型。
- 产品列表／详情：显示动态业务分类，并以表格展示两类价格区间。
- 工作台入口：仅在临时环境与管理员权限下显示。

### 测试

- 迁移与真实 PostgreSQL 约束测试。
- 模板结构、下拉与结构版本测试。
- 两 Sheet 解析、重复、冲突、过期、原子提交和幂等测试。
- 产品列表／详情及五阶段页面组件测试。
- 新库端到端：下载模板 → 填写 → 上传 → 检查 → 预览 → 提交 → 查询 → 回滚。

## 9. 不在本轮范围

- 不迁移当前生产产品或历史价格到新库。
- 不把正式订单、匹配、询价、图片或 Oracle 扫描切换到新库。
- 不让用户在导入检查页面直接创建港口、供应商或商品分类；应先在相应数据表维护。
- 不支持 CSV、旧 `.xls`、公式计算字段或跨多个文件拼接导入。
- 不在第一版允许“忽略错误行后部分提交”。
- 不移除旧产品上传／已有产品更新页面；待新库验收后另行决定迁移和清理。

## 10. 验收门槛

1. 新迁移可在空 PostgreSQL 安装并可从 0036 升级；重复安装被安全拒绝或幂等处理。
2. 数据库确实拒绝同港口重复产品代码，允许同代码存在于不同港口；国家变化不改变产品身份。
3. 同一产品同类价格区间不能重叠；完全相同边界的不同价格按规则更新。
4. 动态新增／停用字段后，下一次下载模板准确变化；旧模板明确阻止提交。
5. 所有错误均能定位到 Sheet、行、字段和中文原因。
6. 含新产品、扩展字段、采购价和卖价的混合批次一次成功；故意制造任一失败时数据库零部分写入。
7. 连续提交同一批次不会重复创建数据；并发修改能在提交前被识别。
8. 临时页面只连接新库；部署前后审计确认生产数据库、生产服务和 Oracle Job 未变化。

## 11. 被否决的替代方案

1. **生产后端运行时选择数据库**：误写和权限边界风险过高，否决。
2. **继续把产品与所有价格塞在一个 Sheet 的重复行里**：字段更新归属模糊，产品资料容易互相覆盖，否决。
3. **先上传产品，再单独上传价格**：增加一次操作且会产生中间半成品状态，不符合已确认的一次上传，否决。
4. **把业务分类硬编码进 `products`**：与已完成的可配置字段方向冲突，每次调整仍需迁移，否决。
5. **直接改造旧 `v3_staging_products`**：会改变现有生产上传语义并增加回归范围，临时新库阶段不采用。
