# 产品利润率设计

日期：2026-09-28
状态：用户已确认设计，等待实施计划

## 目标

在产品管理中增加系统自动计算的“利润率”，帮助用户直接比较当前页面所显示的采购价和卖价，不再依赖人工心算，也不新增需要维护的第三个价格数据源。

利润率显示在产品列表、产品图库以及新增/编辑产品弹窗。它是只读派生值，不允许人工输入。

## 已确认的业务口径

利润率使用毛利率口径：

```text
利润率 =（卖价 − 采购价）÷ 卖价 × 100%
```

- 采购价读取产品主记录的 `price`，与产品页面“采购价”列一致。
- 卖价读取产品主记录的 `contract_price`，与产品页面“卖价”列一致。
- 本功能不按今天、装船日或价格期间重新选择价格；用户看到哪两个价格，就用哪两个价格计算。
- 缺少采购价、缺少卖价或卖价为 0 时，利润率为空并显示“未配置”。
- 采购价为 0 且卖价大于 0 时，利润率为 100%。
- 采购价高于卖价时保留负利润率，不截断为 0。
- API 和界面均以百分数表达，界面保留两位小数。

## 数据与接口设计

产品 API 响应新增只读字段：

```json
{
  "profit_margin": 20.0
}
```

字段类型为 `number | null`。后端集中实现利润率计算，并在产品序列化时返回；产品列表和单产品接口因此使用相同结果。

不新增数据库列，不修改 `products`、`v3_product_price_periods` 或价格历史表，不创建迁移，也不回填历史数据。采购价或卖价保存后，下一次读取会立即得到重新计算的利润率，不存在派生字段过期问题。

产品价格期间可以拥有自己的金额和币种，但产品管理当前展示的主价格只有一个产品级币种；本功能严格跟随主记录展示，不混用价格期间或汇率换算。

## 前端设计

### 列表视图

在“卖价”后、“状态”前增加“利润率”列。显示规则：

- 大于 0：绿色，例如 `20.00%`。
- 等于 0：中性色，例如 `0.00%`。
- 小于 0：红色，例如 `-12.50%`。
- 空值：灰色“未配置”。

利润率列不改变现有价格列、有效期列或列显示设置的行为。

### 图库视图

在每张产品卡片的卖价附近显示利润率，使用与列表相同的文字、精度和颜色语义。没有完整价格时仍保留卡片其他信息，只显示“利润率未配置”。

### 新增/编辑弹窗

在采购价与卖价区域增加只读“利润率”。用户输入或清空任一价格时，前端使用与后端相同的公式即时预览；保存成功后以后端响应为准。

即时预览逻辑封装为单独的纯函数，并覆盖与后端相同的边界用例，避免三个界面各自实现公式。

## 错误与兼容性

- API 新字段为新增的可空字段，旧调用方可以忽略，现有创建和更新请求不增加必填参数。
- 非数字和负数价格继续由现有价格校验拒绝；利润率计算不放宽价格输入规则。
- 利润率为负数不是系统错误，而是需要用户关注的真实计算结果。
- 未配置利润率不影响产品有效状态、商品匹配、询价生成、订单财务或图片管理。
- 产品价格历史仍只记录原始采购价和卖价；利润率可以由任一历史快照重新计算，因此不单独写历史事件。

## 明确不包含

- 利润率数据库列、迁移、历史回填或人工编辑。
- 按利润率筛选、排序或搜索。
- Excel 导入、导出模板中的利润率字段。
- 价格期间、装船日价格、汇率转换或订单利润计算规则修改。
- 订单财务页、询价、匹配、权限和生产数据修改。

## 验证策略

测试按 `EXPERIENCE.md` 的风险分层执行：

1. 后端针对性测试覆盖正常利润、零利润、负利润、采购价为零、价格缺失和卖价为零，并验证列表/单项 API 的只读字段。
2. 前端纯函数与组件测试覆盖两位小数、颜色语义、未配置状态，以及新增/编辑弹窗的即时更新。
3. 相关产品管理测试与 TypeScript 检查通过后，稳定发布候选运行一次前端生产构建和一次本地完整回归。
4. 功能 PR 合并后由 GitHub `main` 再运行一次完整 CI；同一代码未变化时不重复执行全量测试。
5. 本地阶段不改变生产数据库、Cloud Run、Vercel、Scheduler 或产品数据。

## 验收标准

- 同一产品的列表、图库、编辑弹窗显示相同利润率。
- 采购价 80、卖价 100 时显示 `20.00%`。
- 采购价 100、卖价 80 时显示 `-25.00%` 并使用负值样式。
- 缺少任一价格或卖价为 0 时显示“未配置”。
- 编辑价格时利润率即时更新，保存后刷新页面结果不变。
- 现有产品价格、有效期、价格历史、图库操作和 Excel 导入导出保持不变。
