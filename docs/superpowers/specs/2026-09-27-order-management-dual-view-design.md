## 目标

把现有只按供船安排展开的订单管理长列表改成两个直接、可切换的管理视图：

- `按 PO`：一张 PO 一行，直接处理缺信息、异常和正常订单。
- `按轮次`：一个现有供船安排一行，查看该轮次的 PO 数、商品数和汇总处理状态。

本次只优化订单管理列表的读取与展示，不改变 PO、供船安排、询价、匹配或归类的业务含义。

## 已核实的现状

- 正式页面当前一次读取 33 个供船安排和 78 张 PO，以供船安排为主列表。
- 未分类 PO 固定显示在顶部，已归类 PO 需要展开供船安排才能看到。
- 当前只有关键字和装船日期筛选，没有船名、港口、处理状态、分页或独立 PO 视图。
- `GET /api/order-groups/arrangements` 已返回所有可见 PO 的编号、船名、装船日、港口、商品数、处理状态、当前待处理数和所属供船安排。
- 现有摘要没有 PO 原始商品名称，因此不能诚实支持用户确认的商品名称搜索。

## 数据契约

现有 `GET /api/order-groups/arrangements` 保持 URL、权限、分组和全量返回行为不变，只在每个 PO 摘要增加：

```json
{
  "product_names": ["APPLE GRANNY SMITH", "ORANGE NAVEL"]
}
```

名称只从该 PO 已保存的 `Order.products[].product_name` 读取；只去除首尾空白，忽略空值，并按大小写不敏感、首次出现顺序去重。不得改写内部文本，也不得从匹配结果、供应商商品或 LLM 推断名称。没有商品时返回空数组。

数据库结构不变，不增加迁移。

## 共同页面结构

- 页头保留“订单管理”和“导入 PO”。
- 页头中央增加 `按 PO / 按轮次` 分段切换。
- 两个视图都提供装船日期范围和刷新操作；各自保留独立的关键字、船名、目标港口、状态、日期和分页状态。
- 切换视图不修改数据，不发起写请求。
- 任一筛选条件或每页数量变化后回到第一页。
- `重置`只清除当前视图的筛选，不改变另一个视图。

## 按 PO 视图

默认视图为 `按 PO`，默认每页 50 条，可选 20、50、100。

表格列：

1. PO 编号
2. 船名
3. 装船日期
4. 目标港口
5. 商品数
6. 处理状态
7. 操作

搜索范围为 PO 编号、文件名、船名、目标港口和后端明确返回的原始商品名称，大小写不敏感。船名、目标港口和处理状态使用精确筛选；日期范围只比较已解析的装船日期，缺日期 PO 不会误命中日期范围。

排序规则：缺少归类关键信息的 PO 优先，其余按装船日期从近到远，再按 PO ID 从新到旧。

操作保留现有能力：查看 PO、手动指定供船安排、移至未分类、重新自动归类和删除 PO；只有当前业务状态允许的操作才显示。

## 按轮次视图

“轮次”严格对应现有 `SupplyArrangement / OrderGroup`，不创建新的业务实体。默认每页 20 条，可选 10、20、50。

表格列：

1. 装船日期（同时显示星期）
2. 船名
3. 目标港口
4. PO 数
5. 商品数
6. 处理状态
7. 操作

搜索范围为轮次船名和目标港口。轮次商品数为成员 PO 的 `product_count` 之和；状态由成员 PO 当前状态汇总，不读取历史询价排除项。

未分类 PO 作为一个特殊“未分配”行计入轮次总数，固定排在当前筛选结果最后；它显示未分类 PO 数、商品总数和“需补充信息”。点击进入当前页的按 PO 视图，并启用不暴露为额外下拉项的“仅未分类”范围；该范围会显示在结果摘要中，可由当前视图的“重置”清除。

已分类轮次按装船日期升序排列；缺日期轮次位于有日期轮次之后，未分配行最后。

## 状态语义

PO 状态按以下优先级显示和筛选：

1. 缺少目标港口、船名或装船日期：筛选类别为 `需补充信息`，行内优先显示后端已有的具体未分类原因（没有原因时才显示通用文字）。
2. 分析或询价失败：`处理失败`。
3. 上传、提取、匹配或询价正在进行：`处理中`。
4. 当前 `requires_human_review`：`需处理 N 项`。
5. 其他完成状态：`正常`。

轮次状态取成员 PO 中最高优先级；`需处理`数量为成员 PO 当前 `anomaly_count` 之和。订单级缺信息不得伪装成商品未匹配。

## 可访问性与响应式

- 切换按钮使用 `aria-pressed`，图标按钮有明确 `aria-label`。
- 状态不能只依赖颜色，必须显示文字。
- 表格在窄屏横向滚动，筛选区允许换行。
- 空结果、加载失败和刷新中均有明确反馈。

## 明确不修改

- 数据库和迁移版本。
- 自动归类规则与已存在的人工归类标记。
- 商品匹配、单位换算、异常统计口径和询价版本。
- PO 详情页、供船安排详情页和导入流程。
- 生产 Cloud Run、Vercel、Scheduler 或任何生产数据。

## 验收

- 78 张现有 PO 可在按 PO 视图分页浏览，33 个现有轮次含未分配行可在按轮次视图分页浏览。
- 搜索真实 PO 商品名称只返回包含该原始名称的 PO。
- 船名、港口、日期、状态筛选可组合，重置和分页行为确定。
- PO 与轮次的当前待处理数量继续沿用已修复的当前问题口径。
- 所有现有写操作仍调用原接口并在成功后刷新列表。
- 后端完整测试、架构检查、前端完整测试、TypeScript 和生产构建通过。
