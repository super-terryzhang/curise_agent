# 自定义数据表与设置页面交付设计

日期：2026-10-06。用户已明确本轮交付范围为创建新表、配置列、录入编辑、关联、校验和历史，并要求设置中心有明确的前端修改页面。本设计将这些能力组成一个可交付的完整流程，而不是只增加数据库表或接口。

状态：交付范围和书面设计已由用户于 2026-10-06 回复“继续”确认，实施计划待审阅及执行方式确认。应用实现、数据库迁移、测试和部署尚未执行。以下实现规则为本轮设计，不表示现有系统已经具备这些能力。

## 交付范围

用户通过设置中心创建独立业务表、配置列、录入和编辑记录、关联其他自定义表的记录，并查看结构与数据修改历史。在支持的字段类型范围内，新增业务表或列不要求数据库迁移、代码修改和重新部署。

本轮不改变现有 products、suppliers、订单、价格期间或单位换算表，不给这些表增加自定义列，不让新字段自动参与商品匹配、价格选择或询价。不包含附件、计算公式、Excel 导入导出、批量编辑、历史一键回滚、独立表级授权或任意 SQL 执行。关联目标限本轮创建的自定义表；现有主数据接入单独设计和交付。

新增模块沿用当前单一公司系统的角色权限，不引入多租户平台。自定义表中录入的内容不得承诺是仅创建人可见的私有数据。

## 已核对的代码接入点

后端位于 `v3_backend/`，已有 SQLAlchemy Base、FastAPI 路由和 Alembic 迁移。`migrations/env.py` 显式导入模型，新模块必须注册；`main.py` 是路由装配入口。`apps/http/startup.py` 在生产和预发布要求数据库 head 与应用迁移 head 完全一致，发布必须处理新旧 head 过渡兼容，不能默认旧镜像可在新 head 下重启。

`domains/settings/models.py` 的 FieldSchema 和 FieldDefinition 关联订单提取模板；它们不是通用建表模块。本轮保留现有字段管理及模板行为，设置页面明确区分订单提取字段与自定义数据表。

`apps/http/_deps.py` 已有 Admin、Writer 和 CurrentUser。Admin 允许 superadmin/admin；Writer 允许 superadmin/admin/employee/finance。新模块复用这些身份验证机制，不创建旁路身份或数据库直连页面。

前端位于 `v3-frontend/`，设置页使用 PageHeader、Tabs 和现有表单组件。本轮沿用当前系统字体、间距、颜色、按钮、分页和中文错误表达，不重设计全站导航。

## 用户页面与操作

设置中心新增“自定义数据表”入口，目标路由为 `/dashboard/settings/data-tables`。列表展示名称、启用或归档状态、启用字段数、启用记录数和结构更新时间；提供新建、打开、重命名、归档及恢复。列表默认显示启用表，可切换查看归档表。计数由服务端分页或聚合查询提供，不逐表加载全部记录。

表详情路由为 `/dashboard/settings/data-tables/[tableId]`，页头显示表名、说明、返回列表和权限提示，下方固定三个标签：

| 标签 | 展示内容 | 用户操作 |
|---|---|---|
| 字段配置 | 名称、类型、必填、唯一、默认值、顺序、状态 | 新增、修改、上移或下移、归档、恢复 |
| 数据记录 | 按字段定义形成的分页表格，固定记录编号列 | 新增记录、打开编辑表单、归档或恢复、筛选与排序 |
| 修改历史 | 操作时间、操作人、对象、操作类型、字段旧值和新值 | 按结构或记录筛选、打开一次修改的详情，只读 |

新建表只需填写名称和可选说明。新建字段使用一个表单，选择类型后只显示该类型相关配置；不要求用户填写字段 ID 或 SQL 列名。记录新增和编辑使用同一动态表单，保存前显示字段错误，失败时保留用户输入；编辑不能自动保存或静默覆盖他人修改。

关联字段配置目标表，记录表单使用可搜索、分页的记录选择器。每张表可选择一列作为记录显示名称，第一版限文本列；没有配置或值为空时显示固定记录编号。同名记录仍显示编号，不能凭名称自动合并。关联后的页面显示可点击的目标记录详情，不递归展开关系链。

无字段、无记录、无关联目标和无历史均有中文空状态。尚无启用字段时不允许创建空记录，并引导有结构权限的人先配置字段。没有权限时隐藏或禁用写按钮并说明原因，不能只在提交后显示无意义的 403。

## 字段类型和规则

第一版支持文本、数字、日期、日期时间、单选、多选、是或否、关联记录共八种类型；系统记录编号、创建时间、更新时间和操作人只读，不允许配置删除。

| 类型 | 保存及校验规则 |
|---|---|
| 文本 | 保存字符串，配置最大长度；单行与多行只改变控件，默认最大长度 4096 字符 |
| 数字 | 使用 Decimal 解析，最多 18 位有效数字和 6 位小数，字段可进一步限制；拒绝 NaN、无限值和布尔值冒充数字 |
| 日期 | 保存严格的 YYYY-MM-DD 字符串，验证实际日历日期；不进行时区换日 |
| 日期时间 | 接口必须带时区，规范化为 UTC ISO 字符串；页面按当前系统日本时区展示与输入转换 |
| 单选 | 保存固定选项 ID，只允许该字段定义的启用选项 |
| 多选 | 保存不重复的固定选项 ID 列表，最多 100 项；必填时至少一项 |
| 是或否 | 保存真正的布尔值，false 是合法填写，不当作空值 |
| 关联记录 | 单个目标记录，独立关联表保存；配置固定目标表，禁止指向其他目标表或不存在记录 |

数字在 JSONB 中保存规范化十进制字符串，并在接口与页面保持字符串传递；服务端数字查询显式转成 numeric，不能按字符串排序。这样不依赖 JavaScript 浮点表达保持精度。日期和数字查询只对相应类型允许的操作符开放。

PATCH 缺失字段表示保持原值，显式 null 表示清空；文本空字符串、多选空列表在非必填字段中可保留，数字空输入转换为 null。必填文本不得只有空白，必填关联不得为空。默认值只在新增记录、字段未提交时应用，不自动回填历史记录，也不覆盖显式清空。

单选和多选的选项使用固定 ID；修改显示名称不改变已保存的选择。停用选项保留历史显示；没有改变该字段的记录编辑保留原值，新增或改变选择不得使用停用选项。

唯一配置第一版限文本和数字。文本精确区分大小写，不进行隐式去空格或模糊合并；配置唯一时最大长度不得超过 200 字符。数字规范化后 1、1.0 和 1.00 是相同值。null 不占唯一值；空文本属于一个真实唯一值。归档记录仍保留唯一值，恢复不会与后来新记录冲突。

每张表最多 100 个字段，每个选择字段最多 100 个选项；单行普通值规范化后不超过 64 KiB。列表默认每页 50 行、最大 100 行。达到限制时明确报错，不声称资源无限；不设置隐含的全系统记录条数业务限制。

## 数据库存储结构

新增六张固定物理表。用户创建的是业务表定义，不执行 CREATE TABLE 或 ALTER TABLE。新增迁移只创建新模块结构，不回填或覆盖现有业务数据。

| 物理表 | 内容及关键约束 |
|---|---|
| v3_data_tables | UUID ID、名称、说明、状态、schema_version、显示字段 ID、操作人与时间；状态和正版本检查 |
| v3_data_fields | UUID ID、table_id、显示名称、类型、required、unique、default_value、config、sort_order、状态；所属表外键，类型和配置由服务验证 |
| v3_data_records | UUID ID、table_id、values、revision、schema_version、状态、操作人与时间；values 是对象，版本大于零，所属表外键 |
| v3_data_links | 源表和记录 ID、字段 ID、目标表和记录 ID；一行一关联字段只有一个值，源记录及字段必须同表，目标记录必须属于配置的目标表 |
| v3_data_unique_values | 字段 ID、源表和行 ID、规范化值；字段加规范化值唯一，行加字段唯一，字段和行属于同表 |
| v3_data_changes | UUID ID、表 ID、可选字段或行 ID、操作人、时间、操作类型、前后快照、结构版本、行版本及字段显示快照；应用仅追加，不暴露更新或删除接口 |

普通 values 使用固定字段 UUID 字符串作键，不存显示名称作键。关联值只在 links 中保存一个权威来源，响应时合并成动态表单值；values 不能保存第二份关系。选择选项和类型配置使用 JSONB。SQLAlchemy 对 PostgreSQL 使用 JSONB，对现有 SQLite 单元测试使用 JSON variant；PostgreSQL 专项测试不能被 SQLite 结果代替。

字段和记录建立 `(table_id, id)` 复合唯一键，关联和唯一值使用复合外键约束，防止有效 ID 被用到错误的表。字段定义另设专用 target_table_id，关联字段必须非空，其他类型必须为空；links 对字段 ID、源表和目标表建立组合外键，使目标表与字段配置一致。类型、状态和权限仍由服务验证。所有外键删除策略禁止意外级联销毁业务记录。

表、字段和记录主要状态为 active/archived。索引覆盖所属表加状态加稳定分页顺序、记录修改时间、关联目标查询和唯一值查找；普通 values 建立受控的 JSONB 查询索引，数字范围和排序必须用真实执行计划核验，不能把 GIN 索引等同于所有排序都有索引。

## 事务和并发规则

新增或编辑记录的顺序固定为身份和角色检查、读取并锁定当前结构、校验提交结构版本、锁定编辑行并验证 revision、校验值、更新关联与唯一值、追加历史、提交。任一步失败都回滚，不留下只写了一半的记录。PATCH 必须先合并原值再验证完整记录。

结构编辑取得表的排他行锁；记录写入持有结构的共享行锁，确保验证期间结构不能变。涉及多个目标表时按表 ID 排序取锁，再按记录 ID 排序取锁，防止相反顺序形成死锁。目标记录使用能阻止并发归档的锁；归档与关联校验不能只依赖提交前一次查询。

记录编辑提交 expected_revision 和 schema_version，结构修改提交 expected_schema_version。过期版本返回 409 并说明需要刷新；不自动覆盖、不自动重试保存用户编辑。所有 schema_version 变化与对应结构历史在同一事务提交。

唯一值依赖数据库 UNIQUE，而非只有“先查询是否重复”。开启唯一时在结构锁下扫描现存值，包括归档记录，发现冲突返回具体记录；完全成功才创建全部占位并启用配置。取消唯一时在同一事务移除占位；归档字段则保留占位和历史。普通记录保存不修改表的结构更新时间，避免持有共享结构锁时再升级为排他锁。

## 修改与归档的数据保护

字段重命名、顺序变化和显示方式修改允许进行，固定 ID 不变。已存在任何记录时，禁止直接改变字段类型或关联目标表，提示新建字段并整理数据；第一版不提供批量类型转换。

添加必填字段或将已有字段改为必填必须检查现有启用记录；缺值时拒绝并列出记录，不自动补默认值。建议用户先加可选字段、填写数据，再改必填。添加唯一约束同样先检查冲突。修改数字精度、文本长度或停用已用选项均保留历史；收紧校验导致现存启用记录不合法时拒绝，选项停用采用前述保留旧值规则。

字段归档后隐藏且禁止修改，原 values、关系、唯一占位和历史保留；恢复前重新检查配置和记录合法性。显示名称字段归档时同时清空表的显示字段配置，选择器回退到记录编号。

目标记录仍被启用源表的启用记录及启用关联字段引用时，禁止归档并列出引用；归档目标表时同样检查启用关联字段和引用。归档来源表后这些关系保留但不算启用引用；恢复来源表、记录或字段时必须重新校验目标状态和所有相关约束，失败时保留归档状态。第一版不提供任何物理删除按钮。

## 权限与历史

管理员和超级管理员管理表、字段和表归档；Writer 角色录入、编辑、归档或恢复记录；这些角色均可读取本模块记录和历史。其他角色明确返回 403。第一版不新增逐表私有权限，页面应提示公司授权角色共享访问。

前端根据角色呈现按钮，但后端对每个入口独立检查角色、表状态和记录归属。不能通过更换 URL、伪造字段 ID 或提交其他表记录绕过校验；所有查询参数和值使用 SQLAlchemy 参数绑定。

历史包括建表、改名、字段添加或修改或归档或恢复、记录创建或更新或归档或恢复。保存固定 ID 和当时的字段、选项、关系显示快照，避免今天改名使过去的变更记录看不懂。历史不允许编辑，也不混用 identity 安全事件白名单保存业务字段。

## 接口和错误契约

新增 `apps/http/data_tables.py`，前缀 `/api/data-tables`；路由只做身份验证、请求解析、调用服务和错误转换。业务规则位于 `domains/dynamic_data/`，不直接侵入订单、masterdata 或 agent 内部。

接口覆盖表列表及创建、表详情及修改、字段列表及创建及修改、记录分页及新增及修改、关联目标搜索、历史分页。归档和恢复使用明确的 action 接口，不提供会物理删除内容的 DELETE。配置发布立即生效，不增加草稿发布系统。

错误响应包含稳定 code、中文 message 和 issues 数组；单项 issue 包含 table_id、可选 record_id、field_id、当前显示名称和原因。类型错误、必填缺失、停用选项、关联错误、重复值和结构过期分别编码。400/422 用于输入问题，409 用于版本或唯一冲突，403 用于权限，404 用于不存在资源；未预期异常保存脱敏日志和请求关联信息，页面保留输入但不伪报保存成功。

第一版保存一条记录，没有批量半成功语义。网络响应丢失后新增记录不能盲目重发 POST；客户端生成记录 UUID，服务将提交内容、所属表和操作人与原创建历史中的规范化请求比较：相同创建请求返回已有记录并带当前版本，不同请求返回冲突，不把重试当成新增另一行。创建历史保留原创建请求，不能拿后来编辑的当前值判断原请求是否相同。结构创建同样采用客户端 UUID 和原创建请求比较；更新重试通过版本与重新读取核对，不静默重复写历史。

## 代码范围与技术债务边界

后端新增 `domains/dynamic_data/{models,schemas,errors,repository,validation,service,query}.py`，按职责进一步拆分结构、记录及历史服务，避免大文件。接入点为新路由、main、迁移模型注册和测试模型注册。价格、匹配及现有上传入口保持不变。

前端新增 `src/lib/data-tables-api.ts`、设置列表和详情路由、结构表单、动态记录表单、关联选择器及只读历史组件；修改设置中心入口。复用既有 API 客户端、PageHeader、表格和表单组件，前端不写第二套权威校验规则。

针对性技术债务清理限本模块重复校验、硬编码类型映射和不一致错误表达；旧订单提取字段管理保持其业务行为。不顺手搬迁 PO 测试目录，不修旧匹配与异常污染，不重做全站数据页面。未完成的 PO 测试结构设计与已诊断缺陷继续在原文档中保留。

## 验证与交付标准

| 层次 | 必须证明的内容 |
|---|---|
| 类型单元测试 | 八种类型正常及非法值、空值与 false/0、默认值、精度、日期、选项及资源限制 |
| 数据库集成 | 表字段和行归属、关联外键、唯一值、事务原子性、归档和恢复、历史快照 |
| PostgreSQL 专项 | 并发相同唯一值只有一条成功、旧版本不能覆盖、新结构与记录写入不能错配、关联和归档竞态、真实 JSONB 筛选及数字排序 |
| 接口测试 | 每个角色、跨表 ID、参数注入、未知字段、版本冲突、创建重试不重复、中文行字段错误 |
| 前端测试 | 入口可见、动态控件、增改保存、无权限状态、关联搜索及选择、错误定位保留输入、分页、结构过期和历史展示 |
| 离线完整路径 | 创建两张表、配置八种字段、创建目标行、关联保存、修改及查看旧新值、制造错误、归档和恢复；重新登录后数据仍一致 |
| 既有功能回归 | 产品编辑、独立价格期间、批量更新、PO 匹配、询价和鉴权未被新模块改变 |

小阶段只运行对应测试；跨模块连通后运行本模块完整路径；稳定候选运行一次本地完整回归和一次 GitHub 完整 CI。只有 SQLite 通过或页面能打开不能算数据库和业务验收通过。验证使用合成资料或明确授权的测试资料，默认不连接生产、不调用模型、不发送邮件。

用户最终应能从设置中心独立完成“建表 → 配置列 → 新增记录 → 关联另一张自定义表 → 编辑 → 查看修改历史”，遇到错误能看到具体字段和原因，刷新和重新登录后数据保留。不能以交付接口代替交付页面。

## 发布与回退设计

本轮数据库为只增新表的扩展迁移，不删除现有列。实施时核对实际 migration head，再确定迁移编号，不从历史文档猜生产版本。

先在受控 PostgreSQL 演练迁移、启动和回退。由于当前 head 精确检查，发布前先构建仅包含此次新旧 head 允许集合的过渡版本，确保相关 HTTP 服务、Oracle Job 及使用相同启动检查的后台入口可在迁移前后运行。仅验证通过的两个 head 可接受，不永久关闭启动验证，也不允许任意未来 head。

生产顺序为核验当前制品和 head、备份、部署兼容过渡版本并验证现有关键路径、运行扩展迁移、验证六表和约束、部署最终后端及相关 Job、部署前端、只读冒烟验证。最终版本恢复精确 head 校验；记录镜像 digest、后端 revision、前端 deployment 和 Job 版本。

回退优先关闭新入口并回到兼容过渡版本，保留新增表和用户已录入资料；不得用 downgrade 删除新增表来回退功能。尚无用户写入时也不自动删表，物理数据删除仍需单独授权。真实生产写入验收仅在明确授权的测试表中进行；未授权时生产只读冒烟与用户自测分开报告。

## 交付阶段

1. 用户审阅此书面设计，确认范围、页面入口、权限与数据保护规则。
2. 编写逐文件实施计划，列明每项修改、测试命令、验收证据和发布依赖，由用户确认执行方式。
3. 分阶段实现数据库与服务、接口、设置页面、关联与历史，每阶段维护进度和针对性测试。
4. 完成完整路径、PostgreSQL 并发与迁移、既有业务回归及自审，交付本地验收。
5. 按发布授权执行合并、推送和部署，更新生产核验记录，再交付用户检查。

功能完成、上线完成、发布收尾分别记录，不用设计完成代替实现完成。上述阶段尚未实施的事项保留在进度记录中。
