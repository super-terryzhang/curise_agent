# 商品单位换算规则与 PO165047CCI 验证设计

日期：2026-09-24

## 目标与成功标准

为已匹配到供应商商品的 PO 行提供可复用、可审核、可失效的单位换算规则。系统必须保留邮轮原始数量和单位，只在规则明确时计算供应商询价数量；规则缺失、冲突、过期、包装变化或产生不可决定的整箱差异时继续提示人工，不猜测、不静默取整，也不让单行问题停止 Oracle 扫描或其他安全行处理。

首个真实验收对象为生产订单 `PO165047CCI`（订单 id 142、交付日 2026-09-23、港口 id 28）。2026-09-24 只读核验结果为 56 行：53 行已匹配，3 行未匹配；已匹配单位组合是 46 行 `KG2.2→KG`、4 行 `CA22.0→CA`，以及各 1 行 `CA13.22→CA`、`CA15.0→CA`、`CA2.27→CT`。换算系统只处理 53 个已匹配行，3 个未匹配行继续归入商品匹配问题，不得被单位规则伪装成已解决。

## 当前系统事实

- 商品表只有自由文本 `unit`、`unit_size`、`pack_size`，没有可复用换算关系。
- 当前人工操作把 `source_quantity`、`source_unit`、`rfq_quantity`、`rfq_unit` 和 `conversion_evidence` 写入单张订单的商品 JSON；下一张订单无法复用。
- 无人值守询价的旧预检把人工批准绑定到来源文件、版本和行，且用组合单位数字直接推导基础数量；它不能覆盖可复用规则、包装变更和多种规则作用域。
- 生产数据库 head 是 `0030_direct_bulk_images`；本功能需要新的 expand-only 迁移，不能修改或猜测回填现有商品和订单。

## 方案比较

### 方案 A：给 `products` 增加一个换算系数

拒绝。一个商品可能出现多个邮轮单位、目标单位、包装版本和有效期间，单列无法说明“从什么单位换到什么单位”，也不能保存审核与失效记录。

### 方案 B：继续只把结果写进订单 JSON

保留为单行兜底，但不能作为自动化方案。它安全地保存了一次人工决定，却会让相同商品和相同包装在每张 PO 中重复处理。

### 方案 C：分作用域的换算规则表加独立计算服务

采用。规则保存“多少来源单位等于多少目标单位”，支持来源单位级规则和商品包装级规则；标准物理换算由经过测试的代码常量提供，订单只保存本次命中的规则快照。这样既能批量覆盖 `KG2.2→KG`，也能把 `CA2.27→CT` 限定在具体商品与包装。

## 数据模型

新增表 `v3_unit_conversion_rules`，建议迁移号为 `0031_unit_conversion_rules`。表名不限定为商品，是因为它同时保存来源单位级和商品包装级规则；现有 `products` 字段和订单 JSON 保持兼容，不进行数据回填。

| 字段 | 约束与含义 |
|---|---|
| `id` | 整数主键 |
| `scope_type` | `source_unit` 或 `product` |
| `product_id` | `product` 作用域必填，外键 `products.id`；`source_unit` 作用域必须为空 |
| `source_system` | 来源系统，首期为 `oracle` |
| `source_unit` | 规范化后的邮轮原始单位，例如 `KG2.2` |
| `target_unit` | 供应商询价单位，例如 `KG` 或 `CT` |
| `source_quantity` | 换算关系左侧正数，使用 `NUMERIC(20,10)`，不使用浮点数 |
| `target_quantity` | 换算关系右侧正数，使用 `NUMERIC(20,10)`，不使用浮点数 |
| `target_step` | 可选的供应商订购步长；未知时为空，不默认 1 |
| `break_pack` | 可空布尔值；空表示尚未确认，不把“未知”当成允许或禁止 |
| `pack_signature` | 商品作用域规则创建时的 `unit/unit_size/pack_size` 规范化指纹 |
| `status` | `draft`、`verified` 或 `retired` |
| `evidence` | 非空审核依据，不允许只写“系统判断” |
| `valid_from` / `valid_to` | 可空有效期间，结束不得早于开始 |
| `verified_by` / `verified_at` | `verified` 状态必填的确认人和时间 |
| `created_by` / `updated_by` | 创建与最近修改的操作人 id |
| `revision` | 乐观锁版本，初始值 1 |
| `created_at` / `updated_at` | 创建和更新时间 |

换算公式固定为：

```text
target = source × target_quantity ÷ source_quantity
```

示例：`6 KG = 1 CT` 保存为 `source_quantity=6`、`target_quantity=1`；`1 CA2.27 = 1 CT` 保存为两个数量都为 1。公式使用 `Decimal`，保留完整计算值，展示层可以格式化但不得改变业务数量。

数据库检查约束保证数量为正、状态合法、作用域与 `product_id` 一致、有效期合法。两个 partial unique index 分别防止同一来源单位作用域和同一商品作用域同时存在多条已验证规则；新版本必须先停用旧版本，不能依赖查询顺序选择冲突规则。

## 规则作用域与选择顺序

系统依次执行：

1. 原始单位与供应商单位规范化后相同：数量保持不变，不访问规则表。
2. 两边是已支持的同维度物理单位，例如 `LB→KG`：使用固定、可测试的标准换算常量。
3. 查找当前 `product_id`、来源系统、来源单位、目标单位和当前包装指纹完全一致的 `verified` 商品规则。
4. 没有商品规则时，查找来源系统、来源单位和目标单位完全一致的 `verified` 来源单位规则。
5. 其余情况返回 `UNIT_CONVERSION_REQUIRED`，并展示缺失字段和可审核的候选建议。

商品规则优先于来源单位规则。`draft`、`retired`、过期、未来生效、包装指纹变化或存在冲突的规则均不得自动应用。标准换算只负责重量、体积和计数等确定关系；包装文字解析只能生成候选，不能直接生成 `verified` 规则。

有效期判断沿用当前商品匹配的业务日期：优先使用订单 `delivery_date`，缺失时使用现有 geo 流程已经确定的交付日。订单没有可确认业务日期时，只能应用无有效期限制的规则；不能为了命中规则自行选择订单日或当前日期。

## PO165047CCI 的规则与验收边界

只读数据支持生成以下候选，但数据库迁移不得自动把候选写成已验证业务事实：

| 候选 | 覆盖行数 | 作用域 | 候选关系 |
|---|---:|---|---|
| `KG2.2→KG` | 46 | 来源单位 | `1→1` |
| `CA22.0→CA` | 4 | 来源单位 | `1→1` |
| `CA13.22→CA` | 1 | 来源单位 | `1→1` |
| `CA15.0→CA` | 1 | 来源单位 | `1→1` |
| 商品 1820 `CA2.27→CT` | 1 | 商品包装 | `1→1` 候选，包装快照为 `86gX12` |

前四类的数字后缀不直接乘到供应商数量；候选含义是来源系统的交易单位前缀与目标单位相同，所以供应商询价数量保持 PO 数量。商品 1820 的 `CA2.27→CT` 只有在人工确认双方代表同一包装后才能变成 `verified`；`86g×12≈2.275lb` 只是支持候选的证据，不足以替代业务确认。

当五条规则均为 `verified` 且在有效期内时，影子验证必须得到：53 个已匹配行在单位维度通过，原始数量和单位不变，询价数量分别使用原数量并附带规则 id、revision 和证据快照；3 个未匹配行继续显示 `PRODUCT_NOT_MATCHED`。这不承诺 53 行一定通过价格、供应商、模板等其他检查，只证明单位换算不再错误阻断它们。

如果第五条商品规则仍是 `draft`，系统必须得到 52 行单位通过、商品 1820 的 1 行继续要求确认、3 行继续未匹配。该结果视为正确的安全状态，而不是换算失败。

## 订单与询价快照

规则命中后继续使用现有订单行字段，但把 `conversion_evidence` 扩展为结构化快照：规则 id、revision、作用域、公式两侧数量与单位、包装指纹、证据、确认人和确认时间。已生成询价继续使用自己的 match snapshot，不因规则后来修改而回写历史版本。

用户修改 PO 商品、重新关联商品或商品包装变化时，旧换算快照必须清除并重新判断。手工单行换算继续保留，并明确标记为 `order_row` 作用域；只有用户选择复用且通过规则校验时才创建 `draft` 或 `verified` 规则，不能把一次例外默认为永久规则。

## 用户操作与权限

首期复用现有“登记单位换算依据”入口，增加两个明确选项：

- 仅处理当前订单行：维持现有行为，不创建规则。
- 保存为相同商品与包装的规则：创建商品作用域规则，并保存包装指纹。

来源单位级规则能影响多个商品，只允许具备数据管理权限的用户审核；普通订单处理人员不能通过处理一行 PO 创建全局规则。审核接口必须要求 evidence、当前 revision 和显式作用域，记录操作人，并在保存后重新运行当前订单的匹配与异常检测。

独立规则管理页面、批量导入规则和 AI 自动审批不属于第一版；首期只提供必要的查询、创建草稿、审核、停用和在订单页面复用能力。

## 错误处理与回退

- 没有规则：保留原始数据并返回 `UNIT_CONVERSION_REQUIRED`。
- 规则冲突：返回 `UNIT_CONVERSION_RULE_CONFLICT`，不任选一条。
- 包装变化：返回 `UNIT_CONVERSION_RULE_STALE`，展示旧、新包装。
- 非正数量或无效数值：返回 `QUANTITY_INVALID`。
- 结果不满足已知 `target_step`：返回 `NON_INTEGER_PACKAGE_QUANTITY`；不自动向上或向下取整。
- 只有当结果不满足已知订购步长或需要决定是否拆包时，`break_pack` 为空才要求人工；整数且满足步长的结果不会因为该字段未知而被额外阻断。
- 单行计算异常：隔离该行，Oracle 扫描和其他商品继续；记录可追踪的错误码。

发布采用 expand-first：先迁移空表，再部署能够忽略空表的代码，规则功能由开关控制。关闭开关时继续使用当前单行人工换算，不需要回滚数据库；回滚代码时新表保留但不被旧版本访问。首期不删除旧字段和旧人工证据。

## 测试与验证

### 数据库

- PostgreSQL 和测试数据库均验证 upgrade/downgrade、外键、检查约束、partial unique index、乐观锁和 Decimal 精度。
- 空表迁移不改变 1449 个商品、现有订单、询价或价格数据。

### 换算服务

- 单位相同、标准物理换算、商品规则优先、来源规则回退分别有独立测试。
- `draft`、过期、包装变化、冲突、无效数量、小数包装和未知拆箱状态均有反例测试。
- 所有计算使用 Decimal；不得通过二进制浮点比较决定是否整箱。

### 订单与询价

- 原始 PO 数量和单位保持不变；重跑匹配幂等。
- 改商品、改单位、改包装会清除或拒绝旧规则快照。
- 规则命中写入订单和询价版本快照；规则后来停用不改写历史询价。
- 关闭功能开关时现有单行人工处理行为保持不变。

### PO165047CCI

- 固定 56 行匿名化结构回归夹具，断言 53 matched / 3 not_matched 以及五种已匹配单位组合的精确计数。
- 五条规则全部验证时，53 行不再产生单位换算阻断；商品 1820 的询价数量为 `12 CT`。
- 商品 1820 规则未验证时，只保留该行单位确认问题，其他 52 个已匹配行不受影响。
- 三个未匹配商品仍保持未匹配，证明换算系统没有越权解决商品身份问题。

## 实施边界

本设计批准后才编写实施计划和代码。实现包括迁移、ORM/服务、订单规则应用、最小审核 API 与现有对话框适配、测试、影子验证和进度记录；不在未经再次确认的情况下写入生产规则、迁移生产数据库或部署。
