## 目的与实现范围

用户不再必须下载、修改、重新上传 Excel，而是直接选择地区产品，在页面修改基本信息、已有价格区间或新增价格区间，检查并核对后保存。独立的产品 Excel 上传、导出和图片上传保留。

流程：选择产品 → 选择操作 → 编辑数据 → 核对并保存。对应批准设计 UI_UX_design/08_existing_product_batch_edit 的六张图，第三步分基本信息、修改区间、新增区间三个分支。

- 选择：真实类别、供应商、国家、港口、状态、代码/名称筛选；当前页选择与筛选结果全部选择明确区分，跨页读取失败不产生部分全选，筛选变动会丢弃过期全选请求。
- 目标：采购价与卖价独立；已有区间必须原开始/结束日期精确命中。未找到的产品列出且不自动新增。
- 编辑：统一修改只改明确选择的字段，其他值保留；支持逐行调整。新增期间价格为空，不能猜价，可为同一产品追加多个区间。
- 检查：产品 ID、预期版本、期间归属、金额/日期、主数据引用、期间重叠、最终身份重复由服务端检查，显示具体产品、数据行和原因；核对显示旧/新值，失败保存不丢输入。
- 保存：仅保存变化行，直接模式整个批次成功才写入；审计和批次回滚沿用原管道，直接模式回滚也全批成功才恢复。Excel 模式保留既有逐行容错行为。
- 范围：新增直接编辑模块和 prepare-update HTTP 入口；修改原上传 service 的直接差异/事务保护、前端已有产品更新路由、工作台文案及回滚冲突提示；无新表、无迁移、无 PO/询价/Oracle 改动。

## 技术债清理与复核修复

删除只服务于旧强制 Excel 流程的四个子组件、工作簿包装器、状态机和旧专用测试；共享导出、上传、价格维护及历史保留。新编辑模型、API 和三个 UI 分支分开，未在页面复制价格业务逻辑。

最终独立复核的发现已处理：

1. 基本信息提交/回滚都不得把旧兼容价格同步覆盖到规范期间。
2. 恢复名称/代码前检查其他产品是否占用；同批身份交换按全批最终身份验证，回滚冲突不部分恢复。
3. 保存响应丢失后 GET 批次状态，若已完成恢复成功结果，不盲目重复写入。
4. PostgreSQL 身份变更在产品行锁前取得事务性表锁，避免两个直接批次同时生成重复身份；锁随事务结束释放。
5. 取消也锁住批次行后再检查状态，不能把已保存的 completed 覆盖为 cancelled；前端在这个竞态后重读状态。
6. SQLite 的旧事务模式可能在 RELEASE SAVEPOINT 时先持久化，直接模式明确开启外层事务；测试证实后一行失败或回滚冲突时前行不会残留。

身份变更的表锁会短暂阻止其他产品写入；普通读取不被阻塞，只在涉及名称/代码/国家/港口或身份回滚时使用。其目的不是替代所有既有单产品页面的身份策略，而是保护本轮直接批次的验证/写入一致性。
