# 产品图片上传工作台实施计划

> 每一步完成后更新同目录 `PROGRESS.md`，没有验证证据不得标记完成。

## 1. 建立隔离开发环境与红灯基线

创建独立 worktree/feature branch，并运行当前图片专项测试、前端测试及迁移 head 检查。新增工作台入口、直接批次 API 和排序规则的失败测试，先确认测试能够捕捉缺失行为。

## 2. 实现 0030 数据模型和迁移

扩展批次、暂存行并新增产品图片计划表，完成旧数据 `source_type=zip` 的安全回填。添加 SQLite/PostgreSQL 兼容的 upgrade/downgrade 与模型契约测试。

## 3. 实现逐图暂存与校验服务

实现创建批次、逐文件上传、真实图片解码、明确产品绑定、辅助匹配、容量校验、问题码和临时预览。所有规则集中在领域服务，HTTP 层只做认证、请求解析和错误翻译。

## 4. 实现问题修复、恢复与历史

实现 active batch、批次历史、重新分配产品、排除、替换后的重校验和所有权检查。扩展 GC 清理逐图对象，确保刷新、取消和超时都不会留下不可恢复死锁。

## 5. 实现主图与显示顺序计划

保存现有图片与暂存图片组成的完整最终顺序，校验集合完整性和并发版本。实现“第一张即主图”、恢复默认顺序及键盘/拖拽共用的纯排序逻辑。

## 6. 实现幂等提交和单行重试

提交前重新验证容量和正式图片集合，按产品写入图片并应用最终顺序。用 `committed_image_id` 防止重复创建，失败行保留临时对象并支持单行重试。

## 7. 实现专用工作台页面

新增 `/dashboard/workbench/image-upload` 四步页面并拆分上传、问题、排序、确认和结果组件。工作台卡片改为新路由，数据管理移除重复旧入口，同时保留旧 ZIP 后端兼容。

## 8. 补齐前端与端到端行为测试

覆盖工作台入口、active batch 恢复、Step 2 门禁、中文错误、最终顺序和提交结果。使用后端 API 集成测试验证从创建批次到重试/完成的关键用户路径。

## 9. 技术债务清理与代码审查

检查重复校验、超长组件、失效注释、旧权限不一致和临时兼容分支，并只删除已经有测试保护的死代码。对数据库事务、对象存储清理、并发冲突、权限和可访问性进行独立 review。

## 10. 完整验证与候选发布

运行后端完整 pytest、架构检查、Alembic upgrade/downgrade/upgrade，前端完整 Vitest、TypeScript 和 Next.js build。验证全部通过后提交 feature branch，并确认 diff 不包含密钥、真实文件或无关改动。

## 11. 生产迁移与部署

核对当前生产 revision、镜像、Vercel deployment、数据库 head、产品/订单/询价基线并完成数据库备份。执行 0030、发布后端和前端，保留可回滚工件且不提前切断旧 ZIP API。

## 12. 线上验收与交付

使用受控测试图片验证权限、上传、损坏文件、产品分配、主图、排序、提交、刷新恢复和失败重试，并复核日志与数据库计数。更新生产核验和进度文档后，把正式入口与验收结果交给用户检查。
