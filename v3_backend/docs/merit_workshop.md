## 1. 一艘船靠那覇的下午

先讲一个具体场景，不抽象。

**场景**：一艘 4000 客的外籍邮轮，下周二早上 6 点靠那覇港，停 10 小时。
邮轮采购官星期一上午发邮件来，附件是一份 PDF，里面 380 个 SKU——酒类、生鲜、冻品、杂货混在一起。商品名是英文，部分写法不规范。

**没有系统的话，Merit 的星期一是这样**：

| 时段 | 谁在做什么 |
|---|---|
| 09:00 | 邮件分给三语团队，先看懂哪 380 个商品是什么 |
| 10:30 | 对照内部商品表，挨个翻成日文、对码 |
| 12:00 | 按品类拆——酒类找 A 供、生鲜找 B 供、冻品找 C 供…… |
| 14:00 | 每家供应商有自己的询价表格式，挨个填 |
| 16:00 | 发邮件出去，等回复 |
| 隔日 | 报价回来，挨个对比，问交期 |
| 周一晚到周二早 | 把成本算清楚，确认是否做得下、利润多少 |

整个流程**两个全职人 × 两天**，且依赖于经手员工的经验和记忆。如果这名员工请假、离职，新人接手要重新摸索。

**有了系统之后，星期一是这样**：

| 时段 | 谁在做什么 |
|---|---|
| 09:00 | PDF 拖进网页，三分钟后系统出结果：380 个 SKU 已自动匹配上 Merit 商品库、按品类拆好分给了 11 家供应商 |
| 09:15 | 人在屏幕前快速过一遍，把 5% 没匹配上的手动指认 |
| 09:30 | 点"生成询价"，11 家供应商的专属 Excel 同时生成、可下载、可发出 |
| 09:45 | 当天下午开始收报价，系统自动比对 |
| 周二早 | 到岸成本（货款 + 运费 + 通关 + 仓储 + 配送）系统已算清，按船按品类分摊 |

**变化的本质**：
- 人不再做"翻译 / 拆分 / 填表 / 算账"这种重复劳动
- 人留下来的工作是"判断 / 谈判 / 异常处理 / 关系维护"——真正需要 Merit 团队经验的部分
- 一个员工离职不会把流程带走，因为流程沉淀在系统里

### 2.1 能做（**现在生产环境就在跑**）

## 3. Merit 在系统化之后，多了什么"看不见的库存"

老板平时看的是仓库里的实物库存。系统化让 Merit 多了**第二种库存——数据资产**。它不在仓库里，但是给 Merit 真正的护城河。

### 3.1 五种数据资产

**A. 双语商品库**
- 每个 SKU 都有日 / 英对照、品类绑定、供应商绑定、港口绑定、有效期
- 意义：今天某个员工脑子里的"AAA 牌 BEEF GOLD = 牛肉块"这种隐性知识，从今天起属于公司

**B. 供应商指纹库**
- 每家供应商：用什么 Excel 模板、字段怎么排、最小起订量、付款条件、品类范围、过往响应速度
- 意义：新员工第一天就拥有公司 5 年积累的供应商知识

**C. 邮轮消费画像**
- 每艘船 / 每家邮轮，过去都买什么、什么价位、什么节奏
- 意义：这艘船下次靠港之前，Merit 可以先一步预备货、报价更准、抢单更快

**D. 到岸成本与汇率历史**
- 每张订单的 8 类成本明细 + 多币种结算节点
- 意义：可以回答「我们到底在哪个环节赚 / 亏」，而不是凭印象

**E. Agent 跨会话记忆**
- 公司工作习惯（什么时候发邮件、谁负责什么、特殊客户的偏好）
- 意义：AI 助手会越用越懂 Merit，不是每次从零开始

### 3.2 这些资产值什么钱

**对 Merit 自己**：
- 招聘门槛降低（新员工不用熬 1 年才能独立处理船单）
- 单人产能提升（同样的人数能扛更多船）
- 决策从凭感觉变成有数据

**对买家（如果未来 Merit 想被并购或者引入战投）**：
- 这套数据是 Merit 比同行多出来的、可量化的资产
- 商品库 + 供应商关系 + 邮轮画像，是任何想做这门生意的人都买不到的

**对竞争对手**：
- 即便他们明天也装一套系统，没有这五年的积累，他们的 day-one 表现等于 Merit 的 day-one
- 时间差就是护城河

## 5. 业务痛点（请老板讲，我们听）

这一节是 workshop 的留白题。下面是我**猜的**痛点，请老板对一下哪些是真的、哪些不痛、哪些我漏了。

### 5.1 信息流
- 邮轮 PO 邮件附件多 / 散，每次重新看
- 中英日文混杂，团队成员各自对应不同邮轮
- 同一艘船每次靠港都重头处理一次

### 5.2 供应商关系
- 供应商响应速度差异大，没量化数据
- 报价格式不统一，比价费力
- 临时缺货 / 替换品的沟通成本高
- 付款条件、最小起订量、交期承诺不透明

### 5.3 财务
- 到岸成本（运费 / 通关 / 保险 / 仓储）很难提前算清
- 多币种结算与本币利润换算延迟
- 没有「按邮轮 / 按航次 / 按品类」的利润视角
- 资金周转：客户付款节奏 vs 供应商付款节奏

### 5.4 合规与牌照
- 酒类、食品牌照管理是否依赖第三方？依赖到什么程度？
- 保税仓 / 通关业者协调是否是瓶颈？
- 海关申报错误 / 延误的成本承担？

### 5.5 跨域协同
- 船供和旅行两条线，客户是否重叠？数据要不要打通？
- 集团关联公司（AJX、Three Win 等）的商品 / 供应商共享需求强吗？
- 那覇之外（石垣、宫古）的港口有扩展计划吗？

### 5.6 团队
- 现在多少人扛多少船？瓶颈是人还是流程？
- 新员工上手周期多长？要降到多短才算够？
- 季节性高峰（中国春节 / 樱花季 / 寒假）人手够吗？

### 5.7 讨论目标

老板讲完后，**从这里挑出 Top 3 最痛**，roadmap 优先排它们。

## 6. 技术怎么支撑这一切（精简版）

老板不需要懂技术细节，但有几件事值得知道，因为它们关系到风险与可持续性。

### 6.1 系统站在哪几条腿上

```
   Merit 业务流（前面 5 节讲的内容）
                 ▲
                 │  通过聊天界面 / 网页 / LINE 触发
                 │
   AI 助手层  ──── 18 个业务工具，按权限三档（读 / 写可撤销 / 写需审批）
                 │
   业务规则层 ──── 抽取、匹配、模板、询价、成本，每块独立，可单独换
                 │
   数据层    ──── Supabase（PostgreSQL），所有数据可导出
                 │
   外部能力层 ─── Google Document AI、Gemini、DeepSeek、Kimi、OpenAI
                  ↑ 4 家 LLM 厂商可切换，没绑死
```

### 6.2 三件事值得老板知道

1. **AI 不会替你做主**——所有"删订单 / 改价 / 新建供应商"这类危险动作，AI 都是**先提案、等老板点同意才执行**，全过程有审批日志
2. **数据是 Merit 的**——存在 Supabase 里，可随时全量导出。即使有一天换系统，数据带得走
3. **不绑死任何一家 AI 厂商**——Gemini 涨价 / 宕机 / 被屏蔽，可以一键切到 DeepSeek 或 Kimi，业务不停

### 6.3 当前版本与下一版本

- **v2**（现在生产线上跑的）：已经支撑 2.1 节列的所有业务能力
- **v3**（重写版本）：核心闭环已 85% 完成，差最后一步切流，**前端不动**
- **下一阶段**：补完发票 / 对账闭环（Phase 8）

## 7. 未来三档方向

不是路线图列十几项。按"对老板有意义的程度"分三档。

### 7.1 立刻可做（不需要大投入）

| 方向 | 解决的业务问题 |

### 7.2 中期投入（要老板批准方向）

| 方向 | 解决的业务问题 |
|---|---|

**特点**：需要新建子系统或者打通现有数据。投入 1-3 个月。

### 7.3 长期布局（看战略再定）

| 方向 | 解决的业务问题 |
|---|---|
| 客户自助门户 | 邮轮采购官直接下单，Merit 角色升级 |

| 汇率对冲建议 | 多币种敞口的智能提示 |

**特点**：需要战略判断。这些不是技术能不能做的问题，是商业模式要不要走这一步的问题。

## 8. 风险与依赖

把这一节单独拎出来，因为老板必须知道。

### 8.1 系统断了会怎样

| 哪里断 | 影响 | 我们怎么准备的 |
|---|---|---|
| Supabase（数据库） | 业务停摆 | 每天自动备份，数据可导出，最坏情况切到自建 PostgreSQL |
| Google Cloud（运行环境） | 业务停摆 | 容器化部署，最坏情况切到其他云 |
| 某一家 LLM 厂商 | 该厂商对应能力下降 | 4 家可切，业务不停 |
| Document AI | 抽取慢 / 不准 | 可降级到纯 LLM 抽取 |
| LINE 通道 | LINE 客户暂时联系不上 | 网页和邮件不受影响 |

### 8.2 关键人依赖

- 系统现在主要由开发方维护
- **建议**：Merit 内部需要至少一个对系统熟悉的"业务管理员"，能独立处理 80% 的日常维护（加用户、改主数据、调模板）
- **培养路径**：workshop 之后，明确这个人是谁，安排 2-4 周熟悉

### 8.3 数据合规

- 客户邮轮的 PO 含商业敏感信息
- 当前存储在 Supabase 上（位置：Google 数据中心）
- 如果客户要求"数据不出 X 国 / 不进 AI 模型训练"，需要单独配置——**这是要和老板对一下的事项**
